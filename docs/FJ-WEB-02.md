# FJ-WEB-02 — Direct PDF Download

Прямое скачивание готовой PDF-книги одной кнопкой, без браузерного диалога печати.
Генерация полностью на клиенте через `@react-pdf/renderer` (v4.9.0): бэкенда, API и
выгрузки журналов нет — данные не покидают браузер (проверено E2E, см. ниже).

## Что изменилось

- **Кнопка `Download PDF`** (основная) в тулбаре книги: состояния `Generating PDF…`
  (кнопка блокируется от повторных нажатий) → автоскачивание `ForeverJourney_<Имя>.pdf`;
  при сбое — понятное сообщение и кнопка повтора. Локализация EN/RU.
- **`Print`** (браузерный диалог из FJ-WEB-01) оставлена как вторичная кнопка —
  старая печатная реализация не удалена до подтверждения работы генератора.
- **PDF-книга** (`src/pdf/`): A4, книжная концепция сайта — тёмная кожаная обложка
  с двойной золотой рамкой и угловыми орнаментами, герб, имя/класс/раса/уровень,
  даты пути; вступление со статистикой (сетка карточек); главы по месяцам
  (каждая с новой страницы, общий модуль `src/lib/chapters.ts` с веб-версией);
  записи: тип с иконкой, звезда и золотая подсветка избранного, заголовок,
  дата · локация, полный текст, личная заметка с золотой планкой; финальная
  страница с гербом. Орнаменты — векторный порт 1:1 SVG сайта.
- **Текст остаётся текстом**: ничего не растрируется; выделяется, ищется, копируется
  (проверено извлечением текста движком PDFium — тем же, что во встроенном
  просмотрщике Chrome).
- **Шрифты**: PT Serif (4 начертания) поставляются локально в `src/pdf/fonts/`,
  лицензия SIL OFL 1.1 (файл `OFL.txt` рядом). Латиница + кириллица. Никаких CDN:
  Vite отдаёт TTF как same-origin ассеты, загрузка — только в момент генерации.
- **Ленивая загрузка**: `@react-pdf/renderer` и шрифты уезжают в отдельные чанки
  и импортируются динамически по клику. Основной бандл не вырос (~59 KB gzip),
  чанк генератора ~457 KB gzip грузится один раз по кнопке.
- **Разбивка на страницы**: записи не обрезаются; длинные записи переносятся
  по страницам; главы всегда начинаются с новой страницы; короткие записи
  не разрываются (переносятся целиком, как `break-inside: avoid` на сайте),
  заголовок записи не остаётся без текста (высотная эвристика + неразрывные
  блоки); пустых страниц нет; поля, пергамент и рамка сохраняются на
  страницах продолжения (`fixed`-рамка react-pdf).

## Тестирование

- **Vitest — 79 тестов, все зелёные** (`npm test`), включая новые: sanitize имени
  файла, группировка глав, smoke-рендер PDF в Node (`%PDF-`, > 10 KB).
- **Production build** (`npm run build`) — зелёный; главный бандл без react-pdf.
- **Образцы** (`npm run pdf:samples`): 0 / 19 (demo) / 59 / 80 / 500 записей и
  запись длиннее страницы — `docs/pdf-samples/client-*.pdf`. Время генерации
  в Node: 500 записей (102 страницы, 50 глав) ≈ 0.8 с; демо ≈ 0.2 с.
- **E2E в headless Chrome** (`node scripts/download-pdf-check.mjs`, 6 сценариев:
  demo, 0, 59, 80, long, 500): реальное скачивание файла; MIME блоба
  `application/pdf`; байты начинаются с `%PDF-`; имя файла
  `ForeverJourney_<Персонаж>.pdf` (кириллица работает); busy-состояние кнопки
  фиксируется MutationObserver; **за время генерации все сетевые запросы —
  только same-origin** (9 запросов: чанки и шрифты), данных журнала наружу не уходит.
- **Структура PDF** (`python scripts/verify_pdfs.py`, извлечение текста через
  PDFium): обложка на 1-й странице, главы начинаются с собственных страниц
  (в 500-журнале — все 50), пустых/почти пустых страниц нет, кириллица и латиница
  извлекаются, хвост длинной записи (часть 26) и финальная страница на месте;
  пустой журнал — ровно 4 страницы с «Летопись ждёт первой записи».
- **Регресс печати**: `scripts/print-pdf-check.mjs` + старая часть
  `verify_pdfs.py` — Chrome-печать не сломана (4 PDF, ALL OK).
- **Внешний вид**: страницы отрендерены в PNG и проверены (обложка, вступление,
  главы, финал) — соответствуют предпросмотру.

### Известная проблема text-layer и её обход (font warm-up)

pdfkit 0.20 (внутренности react-pdf) в смешанных кириллица+латиница ранах иногда
записывал **пустую запись** в ToUnicode CMap сабсета (наблюдалось на латинской `X`
в кикере «ГЛАВА IX»): копирование/поиск в Chrome давали мусор («ГЛАВА Z»), а
заголовки поздних глав пропадали из извлечения. Обход: в начало документа
рендерится невидимый «прогревочный» текст (латиница, кириллица, пунктуация) для
каждого начертания — все глифы получают корректные unicode-маппинги при первом
использовании. Проверено бисекцией: без прогрева пустые токены CMap появляются
с 9-й главы, с прогревом — отсутствуют на всех сценариях вплоть до 500 записей.
Побочные эффекты: +60–80 KB к PDF (больше глифов в сабсетах) и алфавитная строка
в текст-слое обложки (видна только при Ctrl+A на 1-й странице).

## Известные ограничения

- Генерация в главном потоке: очень большие журналы (тысячи записей) могут
  подвешивать вкладку на секунды; обработка ошибок через retry-баннер.
- Нет градиентов пергамента/кожи в PDF (ограничение react-pdf) — однотонные фоны,
  оформление передано рамками и орнаментами.
- Мелкие капители сайта эмулируются uppercase + letter-spacing (в PDF нет
  `font-variant: small-caps`).
- Прогревочный текст в текст-слое обложки (см. выше).
- `pypdf` 6.x не умеет читать часть CMap-карт react-pdf (ложные пропуски текста) —
  проверка использует PDFium (`pypdfium2`), движок Chrome.
