# FJ-WEB-06 — Character Archive

Итерация развивает импорт SavedVariables (FJ-WEB-05) в полноценный **архив персонажа**.
FJBOOK1 создаёт книгу приключений; SavedVariables создаёт книгу приключений, дополненную
архивом персонажа — чтобы история сохранилась и после окончания беты, закрытия сервера
или потери доступа к клиенту.

## Как это работает

```
ForeverJourney.lua (байты файла)
  → src/lib/luaparse.ts        безопасный разбор Lua-литералов (без исполнения)
  → src/lib/savedvariables.ts  хроника (FJ-WEB-05) + новый блок CharacterArchive:
                               recoveredHistory (снимок, только initialized=true),
                               professions[], visitedZones[], deathsCounter
  → src/lib/journal.ts         FJJOURNAL v1 + опциональное поле journal.archive
  → src/lib/archive.ts         buildArchiveView() — общий view model для веба и PDF
  → ArchiveSection.tsx / BookDocument.tsx   одинаковые данные и формулировки
```

## Модель архива

`journal.archive` присутствует **только** при импорте SavedVariables; FJBOOK1-путь
(`validateJournal`) неизвестное поле `archive` отбрасывает — экспорты и демо-журнал
работают как раньше. Поле `journey.recovered` из FJ-WEB-05 переехало в
`archive.recovered` (веб и PDF до этой итерации его не показывали).

```ts
interface CharacterArchive {
  recovered?: RecoveredHistory        // снимок: capturedAt, level, completedQuests, playedTotal
  professions: ArchivedProfession[]   // name, skillLevel?, maxSkillLevel?
  zones: ArchivedZoneVisit[]          // name, firstSeenAt?
  deathsCounter?: number              // stats.deaths ровно как объявлено в файле
}
```

Правила (все покрыты тестами):

- `recoveredHistory` (включая `professions`) используется только при `initialized === true`.
- `capturedAt` — дата снимка; `createdAt` — начало ведения журнала (`journey.startedAt`).
- `played.currentLevel` — время игры на текущем уровне; никогда не трактуется как уровень.
- `completedQuests.questIDs` сохраняется в файле, но никогда не порождает воспоминания.
- Неизвестное значение остаётся неизвестным (undefined), валидный ноль сохраняется.
- Числа/строки/массивы/даты валидируются и ограничиваются: уровень 1..1000, квесты
  ≤ 10⁷, время ≤ 2·10⁹ с, навыки ≤ 10⁵ (`maxSkillLevel` только > 0), профессии ≤ 100,
  локации ≤ 5000, строки ≤ 20 000 символов, даты в пределах ECMAScript-диапазона.
- Профессия без сохранённого названия отбрасывается; навык без валидного максимума
  показывается без шкалы; «94 / 150» показывается ровно как сохранено.
- `visitedZones` — собственный учёт зон аддона; не приравнивается к событиям ZONE
  хроники (у Straider 6 локаций против 4 событий ZONE). Понимаются форма-карта
  `["Зона"] = <unix-сек>` (значение-таблица с firstSeen/timestamp тоже принята) и
  форма-массив `{ name|zone, firstSeen|timestamp }`; локация без валидного времени
  остаётся в списке без даты.
- Счётчики ≠ события: `deathsCounter` — сохранённый `stats.deaths` (24 у Straider при
  3 событиях DEATH); если файл счётчик не объявил, плитка смертей в разделе не
  показывается вовсе (посчитанные события не выдаются за сохранённый счётчик).
- Архивы разных персонажей не смешиваются; словари Lua без прототипа — опасные ключи
  (`__proto__`, `constructor`, `toString`) остаются обычными именами локаций/профессий.
- Исходная Lua-таблица целиком в модель не попадает; внешних запросов с содержимым
  файла нет — всё локально в браузере.

## Отображение

Раздел **Character Archive / Архив персонажа** встал между вступлением и главами
(веб: `ArchiveSection.tsx`, PDF: `ArchivePage` в `BookDocument.tsx`; оба рендерят
один view model `buildArchiveView`, порядок блоков одинаков):

1. **Historical Snapshot / Исторический снимок** — плитки уровня/квестов/времени/даты
   снимка (только известные) и обязательное пояснение: «Исторический снимок из
   SavedVariables. Значения могут не соответствовать последнему состоянию персонажа.»
2. **Professions / Профессии** — название, «94 / 150», шкала прогресса при валидном
   максимуме (в вебе — CSS-полоса, в PDF — рамка с заливкой в % ширины).
3. **Explored Locations / Посещённые локации** — хронологический порядок, детерминированный
   tie-break (явная локаль `ru` — урок CI-сбоя из hotfix PR #9), дата первого визита,
   если сохранена; без дублирования в хронику.
4. **Saved Statistics / Сохранённая статистика** — «Смертей (сохранённый счётчик)» и
   «Воспоминаний».

PDF: архив — самостоятельная страница в стиле книги (пергамент, PT Serif, рамка,
разделители), длинные списки перетекают на следующие страницы (у образца Straider
«Сохранённая статистика» корректно перетекла на стр. 4), текст выделяется и ищется.

## UX импорта

- Лендинг явно различает способы: FJBOOK1 — «Книга из игрового экспорта…»,
  SavedVariables — «…дополняется архивом персонажа из того, что сохранилось в файле…».
- Тулбар книги после выбора персонажа: «SavedVariables · схема 3 · воспоминаний: 7 ·
  Архив персонажа» (бейдж только когда файл реально нёс архив).
- FJBOOK1/демо-журнал без архива раздел не показывают; пустые блоки скрываются по
  отдельности.

## Тестовый контракт Straider

Санитизированная фикстура `fixtures/savedvariables/ForeverJourney-straider.lua`
(генерируется `npm run generate:sv`), персонаж `ClassicBetaPvP:Straider` + второй
синтетический `ClassicBetaPvP:Testpilot` (проверка не-смешивания). Реальные имена,
GUID и личные данные в фикстуре отсутствуют.

Ожидания (все закреплены тестами): 7 воспоминаний (4 ZONE + 3 DEATH, ничего
синтетического), 24 в сохранённом счётчике против 3 событий DEATH, снимок: уровень 25,
182 задания, 183 754 с (2 д 3 ч), дата снимка; профессии Горное дело 94/150,
Инженерное дело 91/150, Кулинария 25/75; 6 записей visitedZones; `questIDs` не
увеличивает число воспоминаний; `played.currentLevel` не становится уровнем.

## Пройденные тесты

`npm test` — 307 vitest-тестов, все зелёные (было 284). Регрессии по списку задачи:

1. Корректный исторический снимок — контракт Straider (`savedvariables.test.ts`).
2. Отсутствующий `recoveredHistory` — архив без снимка, раздел скрыт.
3. `initialized = false` — снимок и его профессии отбрасываются, зоны остаются.
4. Частично заполненный снимок — только известные поля (0 — известное значение).
5. Некорректные числа — level 0/-1/1.5, quests < 0, played «many», skillLevel -5,
   maxSkillLevel 0 отбрасываются, не превращаются в нули.
6. Пустые профессии/visitedZones — блоки скрыты; данных нет вовсе — нет и архива.
7. Опасные ключи Lua — `__proto__`/`constructor`/`toString` как имена локаций и
   профессий; загрязнения прототипа нет.
8. Несколько персонажей — архивы Straider и Testpilot не смешиваются.
9. FJBOOK1 без архива — `validateJournal` отбрасывает подсунутое поле `archive`;
   демо-книга без раздела (EN и RU).
10. EN/RU — веб (`app.test.tsx`: полные разделы обоих языков, снятая пометка
    «текущих» статов) и PDF (`BookDocument.test.tsx`: рендер EN/RU в валидный PDF).

Плюс: view model (`archive.test.ts` — формулировки/формат/сортировка/шкалы),
лэндинг-пояснения, сохранение ограничений и безопасности Lua-парсера (прежние тесты
парсера и вредоносного файла не изменены и проходят), отсутствие сети при импорте.

## Известные ограничения

- Точная форма `visitedZones`/`professions` в аддоне подтверждена только описанием
  схемы; парсер принимает карту «имя → секунды» и массив записей — при появлении
  реального файла владельца форму стоит сверить (остальное безопасно игнорируется).
- Актуальные (нежелательные к подмене) уровень/раса/класс и живые счётчики квестов/
  `/played` в SavedVariables отсутствуют — книга их по-прежнему скрывает; архив
  показывает только исторический снимок с пояснением.
- `addonVersion` в фикстуре Straider условная (0.9.8); реальные GUID аддон не пишет,
  сайт их не использует.
- Мобильных автотестов файлового ввода нет (как и в FJ-WEB-05).
