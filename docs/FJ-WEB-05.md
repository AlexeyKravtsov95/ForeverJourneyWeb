# FJ-WEB-05 — Импорт SavedVariables

Итерация добавляет второй способ загрузки журнала: вместо экспортного кода из чата игрок
загружает сам файл базы аддона — `WTF/Account/<ACCOUNT>/SavedVariables/ForeverJourney.lua`
(`ForeverJourneyDB`, `schemaVersion = 3`). Файл разбирается целиком в браузере; ничего
не отправляется в сеть, серверного хранения нет.

## Как это работает

```
ForeverJourney.lua (байты файла)
  → src/lib/luaparse.ts        безопасный разбор подмножества Lua (только литералы,
                               таблицы/globals — словари без прототипа)
  → src/lib/savedvariables.ts  проверка схемы, список персонажей, восстановление
                               текста событий из memory.data (deriveEventText),
                               recoveredHistory как исторический снимок,
                               конвертация выбранного персонажа в FJJOURNAL v1
  → CharacterPicker → Book → BookDocument (PDF)   существующий конвейер книги
```

### Безопасность парсера

- Никакого исполнения: ни `eval`, ни `Function`, ни Lua VM. Ручной посимвольный
  токенайзер поверх байтов файла.
- Принимаются только: присваивания `Имя = значение` на верхнем уровне; значения —
  таблицы, строки (с escape-последовательностями Lua 5.1, включая `\ddd`-байты),
  числа (десятичные, float, экспонента, hex, отрицательные), `true`/`false`/`nil`;
  ключи — строки, числа и bare-идентификаторы; позиционные элементы массива.
- Отклоняются: вызовы функций (`os.execute`, `string.rep`, `loadstring(...)`),
  операторы (`local`, `while`, `for`, `return`), конкатенация и арифметика,
  long-bracket строки (`[[...]]`), блочные комментарии, `\x`/`\z`/`\u{...}`-эскейпы,
  сырые переводы строк внутри строк, непарные скобки.
- Лимиты: 32 МиБ на файл, глубина вложенности 64, 500 000 значений всего,
  100 000 полей на таблицу, 1 МиБ на строку.
- Ошибки парсера содержат только код ошибки и номер строки — содержимое файла
  в сообщения не попадает (проверено тестом).
- Строки собираются как байты и декодируются как UTF-8 (non-fatal): литеральный
  UTF-8 и `\ddd`-последовательности, разбивающие многобайтовый символ, дают
  корректный текст.

### Выбор персонажа

Ключи `characters` — `Realm:Character`. После загрузки показывается экран выбора:
имя, сервер, число воспоминаний, число избранных, диапазон дат. Журналы разных
персонажей не объединяются никогда — книга строится по одному выбранному.

### Безопасные словари

Таблицы Lua и globals — словари без прототипа (`Object.create(null)`): ключи
`__proto__`, `constructor`, `prototype`, `toString` становятся обычными
собственными полями и не могут ни загрязнить цепочку прототипов, ни
«подменить» `schemaVersion`/`characters`/`memories` (покрыто тестами).

## 1. Поля, импортируемые без потерь

| Поле SavedVariables | Куда попадает |
| --- | --- |
| `memory.type` | `JournalMemory.type` (как есть) |
| `memory.source` | `JournalMemory.source` |
| `memory.timestamp` (Unix-секунды) | `JournalMemory.timestamp` (нормализовано в мс) |
| `memory.location` (строка) | `JournalMemory.location` |
| `memory.favorite` | `JournalMemory.favorite` |
| `memory.personalNote` | `JournalMemory.personalNote` (дословно, с переводами строк) |
| `memory.title` / `memory.description`, если аддон их записал | `title` / `description` без изменений |
| `memory.data.title`, `memory.data.note` (ручные записи `MANUAL_MEMORY`/`USER`) | `title` / `description` дословно |
| Ключ персонажа `Realm:Character` | `character.name`, отображение сервера в выборе |
| `character.createdAt` | `journey.startedAt` |
| `character.stats.deaths` | `journey.deaths` |
| `recoveredHistory.completedQuests.count`, `.played.total`, `.level`, `.capturedAt` | `journey.recovered` — исторический снимок; сохраняется в модели и не показывается как текущая статистика |

Таймстемпы без даты, записи без полей и пустые персонажи обрабатываются корректно.

## 2. Отображаемые поля, восстанавливаемые вычислением

- **`title`/`description` автоматических событий** — восстанавливаются из
  `memory.data` по шаблонам, которые `Memories.lua` аддона применяет в рантайме
  (формы подтверждены реальным экспортом и совпадают со словарями
  `src/lib/localize.ts`, поэтому RU-перевод работает автоматически):
  - `ZONE` — `data.zoneName` (fallback `data.zone`, `location.name`):
    «Discovered {зона}» / «Открыта зона: {зона}»;
  - `LEVEL` — `data.level`: «Reached Level {n}» / «Достигнут {n}-й уровень»;
  - `INSTANCE` — `data.instanceName` (fallback `data.instance`, `location.name`):
    «Entered {подземелье}» / «Вход в подземелье: {…}»;
  - `DEATH` — `data.killerName`, fallback `data.killerNameRaw`:
    «Fell in battle — {враг}» / «Пал в бою — {враг}»; при наличии поля
    заклинания (`spellName`/`spell`/`finalBlow`) описание
    «Final blow: {заклинание}.» / «Последний удар: {…}.»;
  - `QUEST_MILESTONE` — счётчик (`quests`/`questCount`/`completedQuests`/`count`):
    «{n} quests completed» / «Выполнено заданий: {n}»;
  - `VICTORY`/`BOSS_VICTORY` — подтверждённые описания («The battle ended in
    victory.», «Final blow: {…}.»); шаблон заголовка с именем босса не
    подтверждён и не собирается.
  Приоритет: (1) сохранённый текст (`memory.title`/`description`, ручные
  `data.title`/`data.note`); (2) проверенные данные события; (3) нейтральная
  подпись типа, если данных нет. Имена, уровни, причины смерти и названия
  заклинаний не выдумываются; шаблоны `BOSS_VICTORY`, `PROFESSION_MILESTONE` и
  `ACHIEVEMENT` не подтверждены — для них текст не восстанавливается.
  Экологические смерти без `killerName`/`killerNameRaw` также остаются без
  заголовка (`data.environmentalType` есть, но его шаблон отображения не
  подтверждён).
- **`typeLabel`** — подпись типа для книги: известным типам выдаются
  английские подписи, которые существующий слой локализации переводит на
  русский; неизвестные типы отображаются своим исходным кодом.
- **Хронологический порядок** — сортировка по времени; при равных таймстемах
  сохраняется исходный порядок импорта (порядок файла) на всей цепочке
  `SavedVariables → Journal → buildChapters → Web/PDF` (стабильная сортировка,
  `buildChapters` больше не переупорядочивает по названию). Записи без даты
  идут в главу «Воспоминания без даты».
- **`journey.deaths` при отсутствии `stats.deaths`** — фактический подсчёт
  записей типа `DEATH`.
- **Диапазон дат на обложке** — из таймстемпов воспоминаний (как и для FJBOOK1).

## 3. Данные, которые невозможно получить из текущих SavedVariables

- **Уровень, раса, класс персонажа** — актуальных значений в файле нет;
  обложка и статистика их скрывают (не подставляют нули).
- **Актуальное число выполненных квестов и `/played`** — живых счётчиков нет.
  В schema v3 есть **`character.recoveredHistory` — исторический снимок**
  (`completedQuests.count`, `played.total`, `level`, `capturedAt`,
  `initialized`), записанный, когда аддон впервые увидел персонажа. Снимок
  разбирается и сохраняется в модели (`JournalJourney.recovered` — расширение
  модели, FJBOOK1-путь не затронут), но **не выдаётся за текущую
  статистику**: плитки «Квестов выполнено»/«Времени в игре» остаются скрытыми.
  Известные и неизвестные значения различаются: в модель попадают только
  фактически присутствующие числовые поля (0 — известное значение).
- **Заголовки/описания событий с неподтверждёнными шаблонами** — если у
  события нет ни сохранённого текста, ни проверенных полей `data`
  (`BOSS_VICTORY` с именем босса, `PROFESSION_MILESTONE`, `ACHIEVEMENT`,
  экологические смерти без убийцы), показывается нейтральная подпись типа
  без выдуманного текста.
- **Локализованные клиентом WoW названия** (имена зон/боссов в клиентской
  локали) — в файле только то, что аддон записал на момент события.

## 4. Пройденные тесты (vitest, 239, все зелёные)

- Парсер: стиль сериализации WoW (CRLF, табы, скобочные ключи), все формы чисел,
  булевы/`nil`, позиционные массивы, дубликаты ключей, комментарии, BOM,
  эскейпы (простые, `\ddd`, мультибайтовый UTF-8 через `\ddd`, переносы строк),
  одиночные кавычки.
- **Опасные ключи**: `__proto__`/`constructor`/`prototype`/`toString` как
  строковые и bare-ключи и как глобал — становятся собственными полями
  словарей без прототипа; `Object.prototype` не загрязняется; унаследованные
  члены не видны как поля; специальный ключ не может подменить
  `schemaVersion`/`characters`/`memories`; метакод остаётся PARSE_ERROR.
- Отказ: вызовы функций, `os.execute`/`loadstring`/`setmetatable`, операторы и
  конкатенация, long-строки, блочные комментарии, битые таблицы, непарные
  скобки, невалидные эскейпы, сырые переводы строк, незакрытые строки; в
  ошибках нет содержимого файла.
- Лимиты: пустой файл, превышение размера/глубины/числа значений/длины строки.
- Конвертер: schema 3, несколько персонажей, разделение realm/name, счётчики
  воспоминаний/избранного/дат, отказ для schema 2, отсутствующей БД, отсутствия
  персонажей, битого и вредоносного файла; ручные записи дословно (кириллица,
  кавычки, `\n`, слэши).
- **Восстановление событий**: шаблоны ZONE/LEVEL/INSTANCE/DEATH (+заклинание)/
  QUEST_MILESTONE/VICTORY по подтверждённым полям `data`; fallback
  `location.name`; сохранённый текст побеждает производный; без данных или с
  неподтверждённым шаблоном — нейтральная подпись, ничего не выдумывается;
  RU-локализация производных шаблонов через `localizeMemory` при дословном
  сохранении авторских записей.
- **recoveredHistory**: полный снимок → `journey.recovered`
  (`capturedAt`/`completedQuests`/`playedTotal`/`level`); частичный снимок
  сохраняет только известные поля (0 — известное значение); мусорная форма и
  отсутствие — поле отсутствует; снимок не попадает в текущие статы.
- **Стабильная сортировка**: порядок файла при равных таймстемах сохраняется
  на всей цепочке SavedVariables → Journal → `buildChapters` → веб-книга
  (позиции в HTML) → PDF (общий `buildChapters`); у `buildChapters` убран
  тай-брейк по названию.
- UI: оба способа импорта и путь к файлу на EN/RU, экран выбора персонажа
  (EN/RU), книга из SavedVariables (восстановленные RU-заголовки, скрытые
  недоступные статы, метки типов, ручной текст), пустая летопись, отсутствие
  обращений к сети во время импорта (заглушка `fetch`, бросающая исключение).
- PDF: журнал, собранный из SavedVariables-файла, рендерится в валидный PDF
  (`BookDocument.test.tsx`).
- Регрессия FJBOOK1: все прежние тесты импорта/книги/PDF проходят;
  мета-строка тулбара локализуется при переключении языка для обоих способов.

`npm test` сам генерирует Lua-фикстуры (`vite.config.ts → globalSetup`), поэтому
прогон работает и на чистом чекауте (каталог `fixtures/` в `.gitignore`).

## 5. Что требуется проверить вручную

1. **Реальный файл владельца**: взять настоящий `ForeverJourney.lua` после `/reload`
   (несколько персонажей, кириллица) и прогнать оба языка + скачивание PDF.
   Реального файла в репозитории нет — все фикстуры синтетические, построенные
   по подтверждённой схеме.
2. **Фактические значения `memory.type`** аддона: словарь известных типов собран
   из типов, известных сайту (`localize.ts`); если аддон использует иные коды,
   они попадут в ветку «неизвестный тип» (безопасно, но подписи будут без RU).
3. **Мобильные браузеры** (iOS Safari / Android Chrome): файловый ввод и экран
   выбора персонажа — автоматических мобильных тестов нет.
4. Большие реальные файлы (десятки МБ): парсер линеен, но время на слабых
   устройствах стоит замерить.

## 6. Нужны ли изменения Lua-части аддона

Сайт не изменяет аддон. Базовое восстановление текста событий уже работает по
`memory.data`; для полной точности желательно:

- подтвердить/дописать шаблоны типов, которых сайт пока не восстанавливает
  (`BOSS_VICTORY` с именем босса, `PROFESSION_MILESTONE`, `ACHIEVEMENT`,
  экологические смерти с `environmentalType`) — либо публично специфицировать
  соответствующие шаблоны `Memories.lua`;
- записывать в SavedVariables финальные `title`/`description` событий, чтобы
  сайт гарантированно показывал тот же текст, что и игровой журнал;
- добавить в профиль актуальные уровень/расу/класс и живые счётчики
  квестов/`/played`, если они нужны в книге (исторический снимок
  `recoveredHistory` сайт уже сохраняет в модели, но не выдаёт за текущие).

Без этих изменений импорт честно показывает всё записанное, восстанавливает
подтверждённое и скрывает недоступное.
