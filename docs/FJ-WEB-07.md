# FJ-WEB-07 — Character Archive: Economy & Quest Registry

Итерация расширяет архив персонажа (FJ-WEB-06) двумя видами исторических данных, которые
аддон Forever Journey уже хранит в SavedVariables: **экономикой** (сохранённые денежные
показатели) и **реестром заданий** (сохранённые идентификаторы выполненных заданий).
Дополнительно в историческом снимке появляется время игры на уровне.

## Как это работает

```
ForeverJourney.lua (байты файла)
  → src/lib/luaparse.ts        безопасный разбор Lua-литералов (без исполнения)
  → src/lib/savedvariables.ts  хроника + CharacterArchive; новыми стали:
                               recoveredHistory.money.current → recovered.moneyBalance
                               recoveredHistory.played.currentLevel → recovered.playedCurrentLevel
                               recoveredHistory.completedQuests.questIDs → recovered.questIDs[]
                               character.money → archive.money { earned, current, spent }
  → src/lib/journal.ts         модель: RecoveredHistory и CharacterArchive расширены
                               опциональными полями (обратно совместимо)
  → src/lib/archive.ts         buildArchiveView(): секции Economy и Quest Registry;
                               buildQuestRegistryCsv(): локальный CSV
  → ArchiveSection.tsx / BookDocument.tsx   одинаковые данные и формулировки
```

## Источники данных и происхождение полей

Денежные значения хранятся в **медных монетах (copper)**. Конвертация — только игровая:
10 000 copper = 1 gold, 100 copper = 1 silver (`formatMoney()` в `src/lib/format.ts`).
Это игровые номиналы, а не валюта с курсом.

| Поле файла | Поле модели | Что это (семантика по контракту задачи) |
|---|---|---|
| `recoveredHistory.money.current` | `archive.recovered.moneyBalance` | баланс в историческом снимке |
| `character.money.current` | `archive.money.current` | последний сохранённый баланс в данных аддона — не обязательно финальный баланс персонажа |
| `character.money.earned` | `archive.money.earned` | положительные изменения баланса, зарегистрированные аддоном |
| `character.money.spent` | `archive.money.spent` | отрицательные изменения баланса, зарегистрированные аддоном |
| `recoveredHistory.played.currentLevel` | `archive.recovered.playedCurrentLevel` | время игры на уровне в секундах — не номер уровня и не суммарное время |
| `recoveredHistory.completedQuests.count` | `archive.recovered.completedQuests` | сохранённый счётчик выполненных заданий |
| `recoveredHistory.completedQuests.questIDs` | `archive.recovered.questIDs` | массив сохранённых quest ID |

`earned`/`spent` — **учтённые аддоном изменения баланса**, а не «доходы и расходы за всю
жизнь персонажа»; формулировки интерфейса специально не усиливаются. Названий заданий в
файле нет — ID никогда не превращаются в названия.

Исходники аддона (`Recovery.lua`, `Journey.lua`, `Storage.lua`) в распоряжении итерации
отсутствовали, поэтому семантика берётся из подтверждённого контракта задачи без
дополнительных утверждений.

## Правила (все покрыты тестами)

- Поля `recoveredHistory` (включая деньги и quest ID снимка) используются только при
  `initialized === true`; поля `character.money` обрабатываются независимо от снимка.
- Неизвестное значение остаётся неизвестным (undefined), валидный ноль сохраняется
  (в т.ч. `earned = 0` и «0c» в выводе).
- Деньги принимаются только безопасными неотрицательными целыми (дробное/отрицательное/
  строковое значение отбрасывается, а не округляется и не зануляется); лимит — игровой
  кап 10 млн золота в меди (10¹⁴), сверх него значение ограничивается. Бесконечности
  (`1e999`) отвергаются ещё безопасным парсером.
- Quest ID принимаются только положительными целыми ≤ 10⁷. Политика обработки задокументирована
  и детерминирована: мусор (строки, 0, отрицательные, дробные, вне диапазона) пропускается,
  повторяющиеся ID схлопываются в первое вхождение по порядку файла, итог capped на
  20 000 записей (как MAX_MEMORIES). Ограничение вместо клампинга: урезанный ID указывал бы
  на другое задание.
- `FJJOURNAL v1` и `FJBOOK1` не меняются: `validateJournal` по-прежнему отбрасывает
  неизвестное поле `archive`, демо-журнал и FJBOOK1-экспорты работают как раньше.
- Исходная Lua-таблица в модели не хранится — только провалидированные поля.
- «Прибыль за всё время» и другие производные показатели не вычисляются и не показываются.

## Что видит пользователь

**Исторический снимок** получает строку «Время игры на уровне / Time played at recorded
level» (11827 с → «3 ч 17 мин 7 с» / «3h 17m 7s») рядом с суммарным временем — через
уже существующий `formatPlayedExact()`. Квестовая плитка из снимка переехала в реестр:
одно и то же сохранённое число не показывается дважды.

**Economy / Экономика** — четыре показателя с подписями из контракта (Баланс на момент
снимка / Balance at snapshot, Последний сохранённый баланс / Last recorded balance,
Учтённые поступления / Tracked gains, Учтённые расходы / Tracked spending) и пояснением,
что показатели сохранены аддоном и могут не отражать окончательное состояние или полную
историю операций. Нулевые номиналы не показываются: 2833 → «28s 33c», валидный ноль → «0c».

**Quest Registry / Реестр заданий** — компактная сводка: сохранённый счётчик и число
сохранённых ID как два независимых значения. Когда они различаются (у Straider 182 и 209),
выводится нейтральное пояснение (формулировки — дословно из контракта). Список ID — в
раскрываемом `<details>`-блоке; CSV скачивается локально (Blob, `QuestRegistry_<Имя>.csv`),
содержит только валидные ID одного персонажа и не выполняет сетевых запросов. Внешних
обращений (Blizzard, Wowhead и т.п.) нет; quest ID не создают воспоминаний в хронике.

**PDF** печатает компактную сводку реестра (оба числа + пояснения) без сотен ID — полный
список доступен в вебе и CSV. Книга Straider выросла с 5 до 6 страниц: архив занял две
страницы (снимок+экономика+реестр, затем профессии+локации), обе содержательные.
Веб и PDF рендерятся из одной view model (`src/lib/archive.ts`).

## Известные ограничения

- `money.current` — последний сохранённый аддоном баланс, а не финальный; `earned`/`spent`
  покрывают только то, что аддон успел учесть. Никаких сумм/балансов не выводится.
- Счётчик и список ID могут расходиться (182 против 209) — оба значения показываются
  как сохранённые, причина расхождения в файле не документирована.
- Названия заданий неизвестны: показываются только числовые ID и CSV; запросы к внешним
  базам в этой итерации сознательно не делаются.
- CSV содержит только ID — без названий, дат и локаций заданий.
- PDF не печатает полный список ID (малоинформативен без названий; для больших журналов
  порождал бы десятки страниц).
