# Release Checklist — Forever Journey Book Creator

Релизный чек-лист публичного запуска `https://journal.mythweld.com`.
Рассчитан на повторное использование перед каждым публичным релизом: команды
приводятся полностью, галочки отмечаются по факту выполнения.

Последний прогон: 2026-10-23, ветка `fj-release-01/readiness`, продакшен
сборка `index-C6YerAlu.js` (совпадает с `main` после PR #6).

## 1. Обязательные проверки перед запуском

Выполняются локально из корня репозитория на свежем `main` (или ветке релиза).

```bash
npm ci                  # чистая установка зависимостей
npm test                # 183 юнит-теста Vitest (парсер FJBOOK1, локализация, PDF, деплой)
npm run build           # production-сборка в dist/
npm run preview -- --host 127.0.0.1 --port 4173 --strictPort   # в отдельном терминале
```

С preview-сервером на `http://127.0.0.1:4173/`:

```bash
node scripts/release-audit.mjs            # пользовательский сценарий (см. ниже)
node scripts/download-pdf-check.mjs       # реальное скачивание PDF в headless Chrome
npm run pdf:samples                       # образцы PDF в docs/pdf-samples/
python scripts/verify_pdfs.py             # текстовая верификация PDF (pypdfium2)
```

`release-audit.mjs` проверяет в headless Chrome (CDP, путь к Chrome —
`C:/Program Files/Google/Chrome/Application/chrome.exe` или `CHROME_PATH`):

- [ ] инкрементальный многочастный импорт: после первых блоков показывается
      статус «не хватает частей» (не ошибка), после вставки остальных — книга;
- [ ] повреждённый код (битая контрольная сумма) даёт понятную ошибку, сообщение
      не содержит фрагментов Base64-пейлоада;
- [ ] переключение RU ↔ EN внутри книги не теряет журнал (число глав и записей
      не меняется), системный интерфейс перелокализуется;
- [ ] мобильные вьюпорты Android 360×800 и iPhone 390×844: лендинг и книга
      рендерятся без горизонтальной прокрутки, кнопка Download PDF доступна.

`download-pdf-check.mjs` проверяет для 7 сценариев (демо, демо в RU, пустой
журнал, 59/80/500 записей, длинная запись): файл реально скачивается, MIME
`application/pdf`, начинается с `%PDF`, имя `ForeverJourney_<Имя>.pdf`,
кнопка показывает busy-состояние, все сетевые запросы во время генерации —
same-origin (данные журнала не покидают сайт).

## 2. Проверки production после автодеплоя

После влития PR в `main` автодеплой (GitHub Actions → VK Cloud, см.
`docs/DEPLOYMENT.md`) публикует сборку. Проверить:

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://journal.mythweld.com/   # 200
# сборка на проде совпадает с локальной (хеши ассетов):
curl -s https://journal.mythweld.com/ | grep -oE 'assets/[a-zA-Z0-9_.-]+\.(js|css)'
grep -oE 'assets/[a-zA-Z0-9_.-]+\.(js|css)' dist/index.html
```

- [ ] `HTTP 200`, `Content-Type: text/html`;
- [ ] хеши `index-*.js` / `index-*.css` на проде равны локальной сборке;
- [ ] TTF-шрифты отдаются CDN: `curl -sI https://journal.mythweld.com/assets/PT_Serif-Web-Regular-*.ttf`
      → `200`, `Content-Type: font/ttf`, `Cache-Control: immutable`;
- [ ] `node scripts/release-audit.mjs https://journal.mythweld.com/` — OK;
- [ ] `node scripts/download-pdf-check.mjs https://journal.mythweld.com/` — OK
      (проверяет и подгрузку шрифтов/чанков реального CDN);
- [ ] `node scripts/cross-browser-check.mjs https://journal.mythweld.com/` — OK
      (Firefox + WebKit, если Playwright установлен, см. раздел 5).

Если index.html на проде отдаёт старую версию — это кеш VK Cloud CDN:
уменьшить TTL для HTML в панели CDN (см. `docs/DEPLOYMENT.md`, раздел
«Кеширование CDN») и повторить проверку.

## 3. Проверка версии аддона на наличие Export Book

Функциональность аддона **невозможно проверить автоматически** из этого
репозитория: исходники аддона (JournalExport.lua и др.) в репозиторий не
входили, формат FJBOOK1 реализован по согласованным в ревью допущениям
(Adler-32 по байтам JSON в hex; нарезка единой Base64-строки; лимиты 512
частей / 20000 записей / 3 МиБ; первый блок 30000 символов, далее по 12000).
Перед публичным анонсом владелец обязан вручную проверить в игре:

- [ ] команда `/fj` открывает журнал Forever Journey;
- [ ] кнопка/команда **Export Book** создаёт блоки `FJBOOK1:…` (или показывает
      их в чате — как реализовано в актуальной версии аддона);
- [ ] одночастный экспорт: скопировать → вставить на сайт → книга собирается;
- [ ] многочастный экспорт (журнал побольше): все части скопированы → сайт
      показывает «Получено N из M» → после последней части книга собирается;
- [ ] код из последней версии аддона проходит проверку контрольной суммы
      (если нет — сравнить допущения выше с JournalExport.lua, формат чексуммы
      `string.format("%08X", b*65536+a)`);
- [ ] экспорт с ру-локалью клиента и с ен-локалью собирается одинаково.

Если реальный формат аддона отличается — **не выпускать сайт публично**, пока
парсер не сведён с Lua-экспортёром (это блокирующая проверка).

## 4. Проверка RU/EN PDF

- [ ] `npm run pdf:samples && python scripts/verify_pdfs.py` — ALL OK
      (проверяет обложку, главы с новых страниц, кириллицу + латиницу, хвост
      длинных записей, RU/EN-образцы локализации);
- [ ] вручную открыть `docs/pdf-samples/client-localization-ru.pdf` и
      `client-localization-en.pdf`: системные события локализованы, личные
      заметки игрока не переведены (дословно как в аддоне);
- [ ] в PDF-просмотрщике выделить и скопировать заголовок «ГЛАВА IX» —
      буфер содержит «ГЛАВА IX», а не «ГЛАВА Z» (регрессия бага pdfkit
      ToUnicode; обход — невидимый font warm-up первой страницей);
- [ ] переключить RU → EN → RU на странице книги и скачать PDF в обеих
      локализациях — содержимое журнала в файле одинаково, различается только
      системный текст.

## 5. Проверка мобильных браузеров

Автоматизированы эмуляции вьюпортов (release-audit.mjs, раздел 1) — этого
недостаточно для релиза. Реальные проверки на устройствах:

- [ ] Android Chrome (реальный телефон): открыть сайт, вставить код (в т.ч.
      многочастный), собрать книгу, скачать PDF; проверить, что файл
      открывается в системном просмотрщике;
- [ ] iOS Safari (реальный iPhone/iPad): тот же сценарий; особое внимание —
      скачивание PDF в Files/«На моём iPhone» и открытие в Books;
- [ ] поворот экрана в альбомный режим: вёрстка не разваливается.

Опциональная автоматизация Firefox/WebKit (Windows):

```bash
npm install --no-save playwright
npx playwright install firefox webkit
node scripts/cross-browser-check.mjs          # firefox + webkit
```

Скрипт проверяет: рендер лендинга, многочастный импорт (126 блоков),
RU/EN-переключение, скачивание PDF (реальный download-интерфейс браузера),
отсутствие cross-origin запросов и ошибок консоли. Playwright в зависимости
проекта не входит и локальную установку не переживает.

Ограничение: WebKit в Playwright — не iOS Safari (нет мобильного Safari,
тач-жестов и файлового провайдера iOS). Эти пункты закрываются только вручную.

## 6. Известные ограничения

- **Формат аддона не подтверждён исходниками** — см. раздел 3; парсер
  написан по допущениям, согласованным в ревью.
- Поддерживается только `FJJOURNAL` `formatVersion: 1`; будущие версии аддона
  потребуют обновления валидатора.
- Лимиты входа: 512 частей, 10 М символов вставки, 3 МиБ декодированного
  JSON, 20000 записей, строки по 20000 символов (сверено с лимитами
  JournalExport.lua по ревью).
- Сверхбольшие журналы (сотни записей) генерируют PDF секунды — кнопка
  показывает «Создание PDF…», это ожидаемо.
- Кеш VK Cloud CDN может несколько минут отдавать старый index.html после
  деплоя (TTL HTML, задаётся в панели CDN).
- Печать браузером (`window.print`) — вторичный путь; основной — Download PDF.
- Реальный iOS Safari и мобильные браузеры Android проверяются только вручную.

## 7. План отката

Сайт полностью статичен, состояние пользователей не хранится — откат безопасен.

1. `git revert <merge-commit> -m 1` плохого PR в `main` и push — автодеплой
   опубликует предыдущую сборку (или запустить workflow вручную: Actions →
   Deploy → Run workflow, см. `docs/DEPLOYMENT.md`).
2. Дождаться зелёного workflow и пройти раздел 2 (проверки production).
3. Если прод всё ещё отдаёт старое — сбросить кеш CDN для `index.html`
   (панель VK Cloud → CDN → сброс кеша) и повторить проверку.
4. Крайний случай (бакет/CDN недоступны): перевести DNS-запись `journal`
   на любой статический хостинг с копией `dist/` (например, бакет Beget),
   о чём уведомить пользователей.
5. Статус-страница/анонс: при публичном анонсе дать ссылку на чек-лист —
   пункт «итоговый статус» фиксирует решение о выпуске.
