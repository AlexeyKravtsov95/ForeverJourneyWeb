# PR: FJ-WEB-01 — Forever Journey Book Creator (первая итерация)

## Что сделано

Отдельное статическое веб-приложение **ForeverJourneyWeb** (React + TypeScript + Vite), которое
превращает экспорт журнала аддона Forever Journey в фэнтезийную книгу с печатью в PDF (A4).
Без backend, БД и аналитики — все данные обрабатываются локально в браузере.

## Архитектура

```
src/
  lib/            # чистая логика без React (полностью покрыта тестами)
    adler32.ts    # Adler-32 (RFC 1950), оптимизация NMAX=5552
    base64.ts     # Base64 ↔ байты + UTF-8 (свой декодер, без платформенных зависимостей;
                  #   принимает непаддированный base64 и ASCII-пробелы внутри)
    fjbook.ts     # парсер FJBOOK1: сборка частей, дубликаты, checksum, лимиты
    journal.ts    # схема FJJOURNAL v1: валидация + нормализация + защита от переполнения
    encode.ts     # эталонный энкодер FJBOOK1 (для демо и тестов)
    format.ts     # даты/месяцы (Intl), время в игре, римские цифры
  components/     # Landing (импорт), Book, Cover, Introduction, MemoryEntry, Ornaments (SVG)
  demo/           # демо-журнал: 19 записей, 5 типов событий, кириллица, избранное
  i18n.ts         # строки интерфейса EN/RU
  styles/         # global/landing/book (пергамент, кожа, золото) + @media print
scripts/
  generate-test-codes.mjs  # независимая реализация экспортёра → fixtures/*.txt
```

Поток данных один: `textarea → importJournal() → валидированный Journal → React-рендер`.

### Формат FJBOOK1

- Блок: `FJBOOK1:<part>/<total>:<checksum>:<base64>`; части принимаются в любом порядке,
  между блоками допустим мусор (текст копипаста из чата).
- Контрольная сумма Adler-32 по исходным байтам JSON; принимается десятичная и hex-запись.
- Поддержаны два способа нарезки: слайсы единой base64-строки (основной) и независимое
  кодирование каждой части (fallback).
- Проверки: заголовки частей, единый `total`, единый checksum по частям, полнота
  (1..N без пропусков), конфликты дубликатов (идентичные дубли игнорируются), UTF-8 (fatal),
  JSON, `format === FJJOURNAL`, `formatVersion === 1`, структура.
- Лимиты: 10 МБ ввода, 512 частей, 5 МБ декодированных данных, 10 000 записей,
  20 000 символов на поле.
- При нехватке частей — не ошибка, а статус «ждём части N, M…» с приглашением доклеить.

## Функциональность

- **Landing**: название, подзаголовок «Turn your adventures into a story worth keeping»,
  поле вставки кода, кнопки Import Journal и Try Demo Journal, инструкция получения кода,
  заметка о приватности. Язык EN/RU (автоопределение + переключатель, запоминается).
- **Book Preview**: обложка (имя, класс/раса/уровень, «My Journey», кожаный переплёт с золотой
  рамкой и угловыми орнаментами), вступление (дата начала пути + статистика: уровень, смерти,
  квесты, время в игре, воспоминания, избранные), главы по месяцам (римская нумерация),
  хронологические записи с типом события, иконкой, датой, локацией, полным текстом,
  личными заметками и золотым выделением избранных.
- **PDF**: `@media print` + `@page A4`; разрыв страницы между листами, обложка отдельным
  листом, `break-inside: avoid` для записей, `break-after: avoid` для заголовков,
  тулбар скрыт, `print-color-adjust: exact` для фонов.
- **Демо** проходит через настоящий многочастный конвейер импорта (8 частей).

## Приватность и безопасность

- Ни одного сетевого запроса с данными; нет аналитики и сторонних API.
- Пользовательский текст рендерится только как текст React (без `dangerouslySetInnerHTML`);
  произвольный Lua/JS из журнала не исполняется.
- Вход ограничен по размеру; поля нормализуются и обрезаются; неизвестные поля отбрасываются
  схемой `journal.ts`.

## Известные ограничения

1. Печать через штатный диалог браузера (Save as PDF) — точность отступов зависит от браузера.
2. Финальный экспортёр аддона ещё не предоставлен: точные команды в инструкции лендинга
   (`/fj`, «Export Book») — предварительные, будут сверены при интеграции.
3. Название частицы `part` и допущения о нарезке base64 (слайсы строки) зафиксированы по
   описанию формата; при расхождениях парсер имеет fallback на попереходное кодирование.
4. Нет (по ограничениям первой итерации): авторизации, backend, облачного хранения,
   импорта SavedVariables, нескольких тем, GitHub Actions, деплоя в VK Cloud.

# Ревью-фиксы (Round 2)

## P0 — Контрольная сумма: uppercase HEX из JournalExport.lua

`checksumMatches()` в `src/lib/fjbook.ts` переписан: контрольная сумма теперь
нормализуется (trim → lowercase → без `0x`) и сравнивается с **десятичной**,
**lowercase HEX** (с ведущими нулями и без) и, главное, **uppercase HEX** —
форматом реального экспортёра (`string.format("%08X", b * 65536 + a)`).
Строгость проверки сохранена ( Adler-32 по исходным байтам JSON).

Тесты: одночастный и многочастный экспорт с uppercase-HEX; Lua-стиль журнал
(Unix-секунды во всех `timestamp` и `exportedAt`) собирается корректно.
Сам файл `JournalExport.lua` в workspace отсутствует — паритет реализован по
его документированному формату из ревью; `npm run generate:codes` создаёт
`fixtures/lua-style.txt` (слайсы base64, как в Lua) и `fixtures/lua-style-perpart.txt`
(поблочное кодирование), оба импортируются (проверено в браузере).

## P1 — Схема дат

- `exportedAt` теперь нормальное число: Unix-секунды / мс / ISO-строка → epoch ms
  (раньше число терялось в `asText`).
- `toTimestamp()` отклоняет значения вне диапазона дат ECMAScript (±8.64e15),
  а `formatDate`/`monthLabel` дополнительно защищены — **RangeError из Intl
  невозможен** (тест на NaN/Infinity/±границах).
- Тесты: секунды/мс/ISO/невалидные/граничные значения для `exportedAt` и `startedAt`.

## P1 — PDF: проверка настоящим выводом Chromium

`scripts/print-pdf-check.mjs` печатает приложение через headless Chrome
(CDP `Page.printToPDF`, `preferCSSPageSize`, A4, `printBackground`),
`scripts/verify_pdfs.py` (pypdf) проверяет результат. Итог — **ALL OK**:

|---|---|---|---|
| demo-book (19 записей) | 9 | 3, 5, 6, 7, 8 | обложка на стр. 1, RU+EN текст, финальная страница, пустых страниц нет |
| journal-59 (59 записей) | 17 | 3, 8, 10, 12, 14 | каждая глава с новой страницы, все записи на месте |

CSS-фикс печати: `box-decoration-break: clone` для `.sheet` — страницы-продолжения

## P2 — Надёжность импорта

- **Base64 и не-ASCII**: декодер пропускает Unicode-пробелы/BOM/ZWSP внутри payload
  и жёстко отвергает остальные не-ASCII символы; парсер предварительно вычищает
  такие символы из всего ввода (чат-копипаст), а «разорванные» переносами строк
  блоки склеиваются (чистые base64-строки-продолжения).
- **Лимит записей**: MAX_MEMORIES = 10 000 с обоснованием в коде — реальный ограничитель
  это 5 МБ декодированного payload; у аддона документированного капа нет.
- **Битые блоки не проходят**: новые тесты — перевёрнутый символ base64 →
  CHECKSUM_MISMATCH; внедрённый не-ASCII символ → CHECKSUM_MISMATCH/INVALID_BASE64;
  при ручной проверке в браузере «подделанный» блок был корректно отвергнут.
