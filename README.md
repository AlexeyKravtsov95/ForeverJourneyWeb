# Forever Journey — Book Creator

Веб-приложение для аддона **Forever Journey** (World of Warcraft: Forever): превращает экспорт
журнала приключений в красивую фэнтезийную книгу, которую можно сохранить в PDF и распечатать.

Всё работает **полностью в браузере**: журнал никуда не отправляется, бэкенда и аналитики нет.

> Полное описание итераций (архитектура, тесты, ограничения) — в [docs/PULL_REQUEST.md](docs/PULL_REQUEST.md),
> [docs/FJ-WEB-02.md](docs/FJ-WEB-02.md) (прямое скачивание PDF) и [docs/FJ-WEB-05.md](docs/FJ-WEB-05.md)
> (импорт SavedVariables) и [docs/FJ-WEB-06.md](docs/FJ-WEB-06.md) (архив персонажа).

## Возможности

- **Импорт формата `FJBOOK1`** — реальный формат экспорта аддона:
  `FJBOOK1:<part>/<total>:<checksum>:<base64>`, где внутри — UTF-8 JSON (`FJJOURNAL`, версия 1),
  а контрольная сумма Adler-32 считается по исходным байтам JSON и пишется экспортёром
  в uppercase-HEX (`string.format("%08X", …)`); сайт принимает также lowercase-HEX и десятичную
  запись. Даты в экспорте — Unix-секунды (также принимаются мс и ISO-строки).
- **Импорт SavedVariables (`ForeverJourney.lua`)** — второй способ (FJ-WEB-05): файл
  `WTF/Account/<ACCOUNT>/SavedVariables/ForeverJourney.lua` (schema 3) загружается целиком
  в браузере и разбирается безопасным парсером Lua (без `eval`/`Function`/Lua VM — только
  литералы: таблицы, строки с escape-последовательностями, числа, булевы; всё остальное
  отклоняется). Затем выбирается один персонаж (`Realm:Name` — журналы разных персонажей
  не объединяются), и его воспоминания конвертируются в ту же модель `FJJOURNAL v1`.
  Заголовки/описания автоматических событий буквально воспроизводят строки
  `Locale.lua` реальных обработчиков: `Memories.lua` (точные заголовки
  экологических смертей из `ENVIRONMENT_TITLE_KEYS` — «Died from a fall»/
  «Погиб при падении», «Drowned»/«Утонул», «Succumbed to exhaustion»/
  «Погиб от истощения», «Perished in fire/lava/slime»/«Погиб в огне/лаве/
  слизи»; фолбэки «Lost to the environment»/«Погиб из-за окружения» и
  «Fell in battle»/«Пал в бою»; причина окружения проверяется раньше
  `killerName`, как в аддоне), `BossVictoryMilestones.lua` (`encounterName`,
  фолбэк «Unknown boss»/«Неизвестный босс», фиксированное «Сражение
  завершилось победой.») и `ProfessionMilestones.lua` (`data.kind`: LEARNED
  «Learned profession: …»/«Изучена профессия: …», MILESTONE «… reached
  skill N»/«…: навык повышен до N», число — `tonumber(milestone)` →
  `tonumber(skillLevel)` → 0). Метки типов — DISCOVERY/ОТКРЫТИЕ,
  LEVEL/УРОВЕНЬ, ВЕХА ЗАДАНИЙ, PROFESSION/ПРОФЕССИЯ, MEMORY/ВОСПОМИНАНИЕ.
  Непроверенные данные (имена, уровни, причины, заклинания) не выдумываются
  (`spellID` без `spellName` не превращается в название), авторский текст не
  переводится. Соответствие конвертера обработчикам зафиксировано эталонной
  таблицей в `src/lib/parity.test.ts` (EN+RU, все типы), которая же
  прогоняется через настоящий FJBOOK1-конвейер для паритета обоих способов.
  Исторический снимок `recoveredHistory` (достоверен только при
  `initialized = true`; `/played` валидируется отдельно, без лимита в 10⁶)
  сохраняется в модели, но не выдаётся за текущую статистику. Актуальных
  уровня, расы, класса, квестов и `/played` в файле нет — соответствующие
  плитки статистики скрываются (нули не показываются). Поддержка
  многочастного экспорта, кириллицы и спецсимволов.
- **Character Archive / Архив персонажа** (FJ-WEB-06 + FJ-WEB-07) — раздел книги только для
  импорта SavedVariables (FJBOOK1-экспорты и демо-журнал его не показывают): исторический снимок
  (`recoveredHistory`) с явным пояснением, что значения могут не соответствовать последнему
  состоянию персонажа, включая время игры на уровне (`played.currentLevel` — длительность,
  никогда не уровень); **Economy / Экономика** (FJ-WEB-07) — четыре сохранённых денежных
  показателя в игровых номиналах (баланс снимка, последний сохранённый баланс, учтённые
  поступления и расходы; 96179 → «9g 61s 79c», нулевые номиналы не показываются, валидный
  ноль — «0c», «прибыль за всё время» не вычисляется); **Quest Registry / Реестр заданий**
  (FJ-WEB-07) — сохранённый счётчик и число сохранённых quest ID как два независимых значения
  (у Straider 182 против 209 — расхождение показывается с нейтральным пояснением), список ID —
  в раскрываемом блоке и в локальном CSV (только валидные ID, без выдуманных названий, без
  сети); профессии с сохранёнными навыками («94 / 150») и шкалой прогресса; посещённые
  локации с датой первого визита (хронологически, детерминированно); счётчик смертей из
  файла, который никогда не подменяется количеством событий хроники (`questIDs` не создают
  воспоминаний, `played.currentLevel` не становится уровнем). Веб-раздел и страницы PDF
  рендерятся из одного view model (`src/lib/archive.ts`); PDF печатает компактную сводку
  реестра без сотен ID, длинные списки перетекают между страницами. FJBOOK1 остаётся книгой
  приключений; SavedVariables — книгой приключений, дополненной архивом персонажа.
  Подробнее — [docs/FJ-WEB-06.md](docs/FJ-WEB-06.md) и
  [docs/FJ-WEB-07.md](docs/FJ-WEB-07.md).
- Поддержка **одного блока и многочастного экспорта** (части можно вставлять в любом порядке,
  дубликаты одинаковых частей игнорируются, при нехватке частей показывается, каких именно).
- Проверка: порядка/полноты частей, дубликатов, контрольной суммы (десятичной и hex),
  версии формата, структуры JSON; лимиты на размер входных данных.
- Корректная обработка **кириллицы, эмодзи и спецсимволов**.
- **Книга**: обложка (имя, класс/раса/уровень), вступление со статистикой, главы по месяцам
  с хронологией записей, датами, локациями, полными текстами, личными заметками и выделением
  избранных воспоминаний.
- **Download PDF** — генерация настоящей книги PDF одной кнопкой целиком в браузере
  (`@react-pdf/renderer`, A4, тот же книжный макет: кожаная обложка с золотыми орнаментами,
  пергаментные страницы, главы с новой страницы, избранные записи подсвечены). Текст
  в PDF остаётся настоящим текстом — выделяется, ищется и копируется. Библиотека и шрифты
  (PT Serif, SIL OFL 1.1) грузятся лениво и только со своего origin; файл называется
  `ForeverJourney_<ИмяПерсонажа>.pdf`. Дополнительно осталась кнопка «Печать» (браузерный
  диалог) — см. «Проверка печатной версии».
- Интерфейс на **английском и русском** (переключатель EN/RU).

## Запуск

```bash
npm install
npm run dev        # дев-сервер
npm test           # тесты Vitest
npm run build      # production-сборка (tsc + vite)
npm run preview    # предпросмотр собранного сайта
```

## Тестовые коды для ручной проверки импорта

```bash
npm run generate:codes
```

Скрипт (независимая реализация экспортёра) создаст папку `fixtures/` с файлами:
`sample-en.txt`, `sample-ru.txt` (кириллица), `lua-style.txt` и `lua-style-perpart.txt`
(паритет с `JournalExport.lua`: uppercase-HEX checksum, Unix-секунды, оба способа нарезки),
`sample-large-80.txt` (80 записей), `sample-empty.txt`, `broken-checksum.txt` (битая
контрольная сумма), `missing-part.txt` (не хватает 2-й части), а также журналы для
PDF-проверки (`journal-59.txt`, `journal-80.txt`, `journal-long.txt`, `journal-500.txt` —
500 записей для нагрузочной проверки). Вставьте содержимое любого файла в поле на сайте
и нажмите «Import Journal». Также можно нажать **Try Demo Journal** — демо-код проходит
через тот же многочастный конвейер импорта.

## Тестовые файлы SavedVariables для ручной проверки импорта

```bash
npm run generate:sv
```

Скрипт создаст `fixtures/savedvariables/` с файлами: `ForeverJourney.lua`
(основная фикстура: 3 персонажа на 2 серверах, кириллица, избранное, ручные записи,
неизвестный тип события, равные таймстемпы, запись без даты; CRLF как в реальном WoW),
`ForeverJourney-straider.lua` (санитизированный архив персонажа FJ-WEB-06:
`ClassicBetaPvP:Straider` — снимок 25/182/183754 с, три профессии, 6 локаций,
24 смерти в счётчике при 3 событиях DEATH; плюс второй персонаж для проверки
не-смешивания), `ForeverJourney-schema2.lua` (старая схема), `ForeverJourney-otherdb.lua`
(нет `ForeverJourneyDB`), `ForeverJourney-broken.lua` (обрыв файла) и
`ForeverJourney-malicious.lua` (опасные конструкции Lua — должны отклоняться).
`npm test` генерирует их автоматически перед прогоном. Реальный SavedVariables-файл
в репозитории отсутствует — финальную совместимость подтвердить после предоставления
владельцем тестового файла.

## Скачивание PDF и его проверка

Кнопка **Download PDF** генерирует книгу в браузере (`@react-pdf/renderer`) и скачивает
`ForeverJourney_<Персонаж>.pdf`. Проверить генератор без браузера можно тем же кодом:

```bash
npm run pdf:samples   # 8 образцов в docs/pdf-samples/client-*.pdf (0/19/59/80/500 записей, длинная запись + пара EN/RU для локализации)
```

Полная E2E-проверка (реальное скачивание из headless Chrome, MIME `application/pdf`,
отсутствие внешних запросов):

```bash
npm run build && npm run preview -- --port 4173 --host 127.0.0.1   # в одном терминале
node scripts/download-pdf-check.mjs                                 # в другом
```

## Проверка печатной версии (настоящий PDF)

```bash
npm run build && npm run preview -- --port 4173 --host 127.0.0.1   # в одном терминале
node scripts/print-pdf-check.mjs                                   # в другом: 4 PDF в docs/pdf-samples/
python -m pip install pypdfium2 && python scripts/verify_pdfs.py   # проверка страниц/глав/текста (Chrome-PDF + клиентские)
```

## Архитектура

```
src/
  lib/            # чистая логика без React
    adler32.ts    # контрольная сумма Adler-32
    base64.ts     # Base64 ↔ байты, UTF-8 (без платформенных зависимостей)
    fjbook.ts     # парсер FJBOOK1: части, дубликаты, checksum, лимиты
    luaparse.ts   # безопасный парсер Lua SavedVariables (литералы, без исполнения)
    savedvariables.ts  # ForeverJourneyDB → список персонажей → FJJOURNAL v1
    journal.ts    # схема FJJOURNAL v1 + валидация/нормализация
    chapters.ts   # группировка записей в главы по месяцам (общая для веба и PDF)
    encode.ts     # энкодер FJBOOK1 (демо и тесты)
    format.ts     # даты, месяцы, время в игре, римские цифры
  pdf/            # генератор PDF (FJ-WEB-02)
    BookDocument.tsx  # книга как react-pdf документ (обложка/вступление/главы/финал)
    ornaments.tsx     # SVG-орнаменты (порт 1:1 с веб-версией)
    registerFonts.ts  # локальная регистрация PT Serif (4 начертания, без CDN)
    fontUrls.ts       # ?url-ассеты шрифтов для браузера (ленивый чанк)
    filename.ts       # sanitize имени персонажа → ForeverJourney_<Name>.pdf
    download.tsx      # динамический импорт, toBlob(), скачивание
    fonts/            # PT Serif TTF + OFL.txt (SIL OFL 1.1)
  components/     # Landing, CharacterPicker, Book, Cover, Introduction, MemoryEntry, Ornaments
  demo/           # демо-журнал (19 записей, кириллица, избранное)
  i18n.ts         # строки EN/RU
  styles/         # пергамент/кожа/золото + print CSS
```

Данные идут по одному пути: `textarea → importJournal() → валидированный Journal → React-рендер`
(для PDF — тот же `Journal` → `BookDocument`). Пользовательский текст выводится только как текст
React (без `dangerouslySetInnerHTML`), произвольный код из журнала не исполняется.

## Ограничения

- Генерация PDF идёт в главном потоке браузера: журналы на тысячи записей могут подвешивать
  вкладку на секунды (500 записей ≈ 1 с на десктопе).
- SavedVariables не содержат актуальных уровня, расы, класса, числа квестов и
  `/played` — эти плитки скрываются вместо подстановки нулей (исторический снимок
  `recoveredHistory` с `initialized = true` хранится в модели, но не показывается
  как текущие значения); текст событий с неподтверждёнными шаблонами
  (`ACHIEVEMENT`, `REPUTATION_MILESTONE`) не восстанавливается и не выдумывается
  (см. docs/FJ-WEB-05.md).
- В PDF нет градиентов пергамента (react-pdf не поддерживает фоновые градиенты) — страницы
  однотонные, оформление сохранено рамкой и орнаментами.
- Браузерная «Печать» (старый путь) оставлена как резервная до полной уверенности в генераторе.
- Нет авторизации, бэкенда, облачного хранения.
- Точные названия команд аддона в инструкции на лендинге будут уточнены при интеграции
  с финальным экспортёром.
